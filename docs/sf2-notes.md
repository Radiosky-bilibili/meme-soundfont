# WAV → SF2 流程笔记

记录从一段 WAV 做成可用的 SoundFont 2 的完整流程，以及过程中确认的结构细节。

## 一、素材准备

1. 截取一段**稳定**的声音（持续音、元音、简单音效）。整句话会糊。
2. 转成：单声道、16-bit PCM、44100 Hz。
3. 去掉首尾的爆音与静音。
4. 确定**根音**：这段采样原本是哪个 MIDI 音高。
   - 用音高检测工具测基频，再换算：`MIDI = 69 + 12 × log2(f / 440)`
   - 例：464 Hz → 69.93 → 取整为 70（A#4）

> 测基频时先低通到 400 Hz 再做自相关，否则泛音会把结果抬高一个八度。

## 二、SF2 的两部分

```
sdta（声音数据）
  └─ smpl   裸 PCM 样本
pdta（数据库，9 张表）
  phdr → pbag → pgen ─┐
                       ├→ inst → ibag → igen ─→ shdr ─→ smpl
  pmod / imod ─────────┘
```

播放器沿着这条链，找到「按这个键时播哪段波形、怎么变调、怎么包络」。

## 三、表顺序（实测）

```
phdr → pbag → pgen → pmod → inst → ibag → igen → imod → shdr
```

部分实现在 `pgen` 与 `pmod` 之间顺序不同，写错会报
`Expected PDTA sub-chunk 'pmod' found invalid id instead`。

## 四、关键参数

### 采样头（shdr）

| 字段 | 作用 |
|---|---|
| start / end | 波形在 smpl 中的起止（**样本数**，不是字节） |
| loopStart / loopEnd | 循环区间，选波形平稳的中间段 |
| sampleRate | 采样率 |
| originalKey | 根音 |
| sampleType | 1 = mono |

### 乐器生成器（igen）

| ID | 名称 | 常用值 |
|---|---|---|
| 43 | keyRange | 0x7f00（0–127） |
| 56 | overridingRootKey | 与 shdr 的根音一致 |
| 54 | sampleModes | 1 = 循环 |
| 33 | attack | 时间值，见下 |
| 36 | sustain | 0 = 最大 |
| 37 | release | 时间值 |
| 53 | sampleID | 指向 shdr 第几条 |

### 预设（phdr / pbag / pgen）

- 每个预设 = 一个音色位（bank + program）
- GM 约定：bank 0 是旋律，bank 128 是鼓
- 做「全替换」时，把 128 个预设全部指向同一个乐器

## 五、时间值的换算

包络时间不是毫秒，是**音分制的对数时间**：

```
秒 = 2^(值 / 1200)
```

| 值 | 秒 |
|---|---|
| 0 | 1 s |
| −1200 | 0.5 s |
| −9000 | ≈ 6 ms |
| −12000 | ≈ 1 ms |

填正数会导致起音变慢，短音符还没爬到音量就被截断。

## 六、调试顺序

1. 先做最小结构（1 采样 / 1 乐器 / 1 预设），确认能出声
2. 测音高：偏高就加大根音，偏低就减小
3. 测时长：长音断开 = 循环没开；短音有咔哒 = attack 太长或 release 太短
4. 测覆盖：只有钢琴出声 = 其他预设没定义

## 七、常见错误

| 现象 | 原因 |
|---|---|
| `Invalid chunk id in INFO chunk` | INFO 子块 ID 必须大写；字符串长度必须是偶数 |
| `pmod ... found invalid id instead` | 表顺序不对，或 pmod/imod 缺失 |
| 只出一两声 | attack 太大 / release 太小 / 时间值填成了正数 |
| 全部静音 | 预设层直接引用采样，跳过了乐器层 |

## 八、兼容性

不同播放器的宽容度差别很大。规范上不合规的地方，有的播放器能容忍、有的直接拒绝加载。

建议始终按规范写：

- INFO 子块 ID 大写
- 字符串 = 内容 + 至少 1 个 `\0`，整体长度为偶数
- 每张表都要有终止记录
- 容器块（LIST）不要额外填充

写完后用两个以上的解析器各加载一次，能发现大部分问题。
